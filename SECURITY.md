# Security Policy

## Supported Versions

The latest stable release is TestForge v1.0.0.

| Version | Supported |
|---|---|
| 1.0.x | Yes — latest stable patch release |
| Release candidates (e.g., 1.0.0-rc.1) | No |

Security issues are assessed against the latest stable release and the latest code on the `main` branch. Users are encouraged to upgrade to the latest stable patch release where possible.

Security fixes and support for future versions will be documented as new releases become available.

## Reporting a Vulnerability

Please do not disclose suspected security vulnerabilities in public GitHub issues or pull requests.

**Preferred reporting method:** Use GitHub's private vulnerability reporting feature for this repository when it is enabled and available.

If private reporting is unavailable, open an issue containing only a brief request for a private reporting channel. Do not include exploit instructions, credentials, API tokens, personal information, or sensitive logs in a public issue.

When reporting a vulnerability privately, please include:
- A description of the potential vulnerability.
- The affected component and version or commit, if known.
- The potential impact.
- Minimal reproduction steps and relevant logs, with secrets and personal data removed.

## Response Process

The maintainer will review vulnerability reports as time permits and may request additional information.

The maintainer will assess the issue, determine appropriate remediation, and communicate next steps where possible. No guaranteed response or resolution timeframe is provided.

Please avoid public disclosure of technical details until the issue has been investigated and a disclosure plan has been agreed upon.

## Scope

This policy covers the TestForge repository and its automation framework.

It does not authorize security testing against third-party APIs, websites, infrastructure, or services used by the test suite. Do not access, modify, or disrupt third-party systems without permission.
